# quoteGEN-AI

AI-assisted quotation generator with a React frontend and FastAPI backend.

## Deploy

The repository includes a Netlify build configuration (`netlify.toml`) and a
Render Blueprint (`render.yaml`). Connect the GitHub repository to Netlify to
publish the frontend. In Render, create a Blueprint instance from this
repository and set the prompted environment variables before deploying:

- `GEMINI_API_KEY`: Gemini API key used by the backend.
- `SUPABASE_SERVICE_ROLE_KEY`: Supabase service-role key. Keep this secret and
  enter it only in Render's environment settings; never put it in the repository
  or frontend configuration.
- `CORS_ORIGINS`: set by the Render Blueprint to
  `https://quotegen1-ai.netlify.app`.

The Supabase URL and frontend publishable key are configured in `netlify.toml`.
After Render deploys, set the Netlify environment variable `VITE_API_URL` to
the Render service URL (for example, `https://quotegen-api.onrender.com`) and
trigger a new deploy. Set Supabase's Site URL and allowed redirect URL to
`https://quotegen1-ai.netlify.app` in the Supabase Auth URL settings.

The Render API uses Supabase Auth to verify bearer access tokens. User data is
scoped to the authenticated Supabase user when backend Supabase credentials
are configured.

## Configure Supabase Auth

Run `backend/supabase/schema.sql` in the Supabase SQL Editor. It is safe to
rerun and adds the filterable `business_type` column to the per-user profiles
table. The Business profile page collects business name, type, website, and
address; sign-in email remains part of the Supabase auth account.

In Supabase **Authentication → URL Configuration**:

- Set **Site URL** to `https://quotegen1-ai.netlify.app`.
- Add `https://quotegen1-ai.netlify.app/**` to the allowed redirect URLs so
  the signup confirmation can return to the app with its confirmation marker
  and email query parameter.
- For local development, also allow `http://localhost:5173/**`.

In **Authentication → Email Templates → Confirm signup**, set the subject to
`Confirm your quoteGEN email` and paste the HTML from
[`backend/supabase/templates/confirm-signup.html`](backend/supabase/templates/confirm-signup.html)
into the message body. Keep the `{{ .ConfirmationURL }}` template variable
intact; it is the confirmation link generated by Supabase.

The default Supabase mail service may use Supabase's sender identity and has
testing/delivery limits. To send branded production email, configure a custom
SMTP provider in **Authentication → SMTP Settings**, verify the sending domain
with that provider, and set the sender name to `quoteGEN AI`. Never put SMTP
passwords or provider secrets in this repository.

Sign-up asks for a full name and stores it in the Supabase auth user's
`full_name` metadata. Sign-in uses email and password.

## Quotation plan and Flutterwave

New accounts can generate up to 10 new quotations free in any rolling 30-day
period, capped at 3 free quotations per UTC day. A quotation is counted only
after successful generation; regenerating an existing saved quotation does not
use another free quotation. After the free quota is used, one payment of
₦13,310 unlocks unlimited quotations for one calendar month. The payment does
not auto-renew. The price is configured with
`FLUTTERWAVE_MONTHLY_PRICE_NGN` so it can be adjusted when needed.

Run the updated `backend/supabase/schema.sql` in the Supabase SQL Editor. It
creates the per-account billing tables and the atomic quota/payment functions.
The free allowance is 10 new quotations in a rolling 30-day period, capped at
3 free quotations per UTC day. The dashboard shows daily and rolling-window
usage. Re-run the updated schema to install these server-side limits.

The monthly plan is not activated from the browser return URL alone: the
backend verifies transaction status, reference, currency, and amount directly
with Flutterwave before granting access.

## Draft a proposal from a job description

In **Create a proposal**, choose **Describe a job** to provide the scope, what
the proposal should cover, and its target total in Naira. The backend reads
text from the signed-in user's active master proposal, removes its client
identifiers and old prices, and uses the remaining work categories and detail
as a guide. It expands each requested area into practical tasks and work phases.
The AI suggests weighted cost lines, and the backend allocates those weights
so the line items sum exactly to the target before rendering the proposal with
the same master-template design and saving it as a document. The
AI-generated prices are estimates, not a rate card; review every line against
approved rates before sending. The active master must be a text-searchable PDF.
Job drafting requires `GEMINI_API_KEY` on the backend.

In Render, set these backend environment variables:

- `FLUTTERWAVE_SECRET_KEY`: the Flutterwave secret API key; keep it server-side.
- `FLUTTERWAVE_WEBHOOK_SECRET_HASH`: a random secret hash you also set in
  Flutterwave's webhook settings.
- `FLUTTERWAVE_MONTHLY_PRICE_NGN`: `13310` (change this value when the plan
  price changes).
- `FRONTEND_URL`: `https://quotegen1-ai.netlify.app`.

In Flutterwave's dashboard, configure the webhook URL as
`https://YOUR-RENDER-SERVICE.onrender.com/billing/flutterwave/webhook`, choose
the `charge.completed` event, and use the same webhook secret hash configured
in Render. Start with Flutterwave test-mode credentials and test the whole
checkout/verification flow before switching to live credentials.
